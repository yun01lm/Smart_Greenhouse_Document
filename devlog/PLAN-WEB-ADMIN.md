# Web 端系统管理员账号整改 — 需求记录与实施计划（待批准）

> 本文档记录用户 2026-08-04 提出的系统管理员（ADMIN）账号 Web 端整改需求。
> 文档仓库规则：只追加不修改；本计划经用户批准后按轮次执行。

## 一、需求记录（用户原述整理，共 12 条）

### 1. AI 问答
- 登录后首界面应为"数据总览"，不是 AI 问答
- AI 问答当前为 Mock 模式，需完善为真实可用
- 问答必须限定农业知识范围，防止被非农业用途盗用
- 用户将提供真实 API Key：不得上传 GitHub、不得通过翻代码找到

### 2. 数据总览（管理员版）
- 管理员能看到所有用户信息，数据总览应展示"一片地区"的整体概览
- 环境数据取该地区农户平均值/中位值，或不做细化环境数据
- "环境趋势"改为"预警总览"：该地区预警总数 + 预警类型分布
- "大棚健康评分"改为"地区健康评分"（按预警数量评估，规则可后定）
- 保留"最新预警"（该地区所有用户）与"当前天气"（按所选地区查询）

### 3. 地区划分
- 按行政区划：省 / 市 / 县(区) / 乡镇 / 村
- 管理员可选择：某省、某市、某县、某村、或某个具体用户，作为查看范围

### 4. 设备管理（管理员版）
- 看总体数据：设备在线总数、农户在线总数（农户名下至少 1 个传感器在线即在线）
- 按农户查找设备：先找到农户 → 进入该农户的设备管理

### 5. 用户管理
- 保留角色筛选；新增地区筛选（按第 3 点的地区划分），精准定位用户

### 6. 知识库
- 上传文档不可用，需修复
- 文档分类显示 ？？？？乱码，需修复
- 向量化未进行，需完善

### 7. 预警配置
- 系统管理员不需要此界面；仅农户（OWNER）或其名下技术员（WORKER）可用

### 8. 数据导出
- 系统管理员不需要此界面；当前不可用需修复
- 仅农户及其名下技术员可用

### 9. 系统监控
- 与数据总览合并（管理员账号）；其他账号不显示此界面

### 10. 语料管理
- 用户暂无资料，判断当前可能不可用；尽量完善

### 11. 专家工作台
- 功能是"管理员监控专家"，当前功能定位有误
- 专家上线/登录时自动刷新在线状态
- 管理员可查询专家与用户的对话咨询记录，支持查询与导出

### 12. 棚主管理
- 界面存在但功能不对
- 管理员可"进入棚主的 web 管理系统"（以棚主身份查看/操作）
- 需要用户筛选与搜索功能

## 二、总体要求
- 每个角色看到的 Web 管理端页面按角色定位与权限划分，功能各不相同
- 本次先整改系统管理员账号；其他账号后续单独一轮
- 按系统设计架构执行，不损害后续工作，不为解决选择问题搭建多余工具

## 三、现状勘察结论（2026-08-04 代码核对）

### Web 端
- 菜单为静态全量（MainLayout.vue 11 个菜单项，未按角色过滤）；AI 问答排在第一个
- 登录后 router 跳转 /dashboard（数据总览），但菜单首项为 AI 问答
- 各页面均已有对应 API 封装；请求走 src/utils/request.js

### 后端（已具备的基础）
- 角色：ADMIN / OWNER / WORKER / EXPERT；/api/v1/admin/** 仅 ADMIN
- 大棚实体含五级地区：province / city / district / town / village（无独立区划表，地区来源于大棚登记）
- AI Provider 抽象已存在：LlmProvider（mock|deepseek）、EmbeddingProvider（mock|siliconflow）；application-dev.yml 中均为 mock
- 知识库：上传/切片/向量化/Chroma 写入链路已有（仅 .md/.txt）；分类乱码疑为 MySQL 字符集问题
- 专家：AdminExpertController（列表/在线切换/授权记录/统计）+ Chat 模块（对话/消息）
- 监控：AdminMonitorController（设备在线率/告警统计/系统概览）
- 导出：AdminReportController（传感器/预警/控制日志/健康评分 → Excel）
- 语料：AdminCorpusController + DialectCorpus 实体已存在
- 预警：Alert 关联 greenhouse_id；地区级预警需经大棚地区聚合
- 天气：QWeatherService 按 location 查询（当前 provider=mock）

## 四、实施计划（草案，按轮次执行，待批准）

### 轮次 R5 — 用户管理地区筛选（问题 5）

### 轮次 R6 — 知识库修复（问题 6）
- 修复 MySQL 字符集（knowledge_documents 等表）解决分类乱码
- 修复上传链路 + 真实向量化（siliconflow bge-m3）
- 上传成功后自动触发向量化；补强失败提示

### 轮次 R7 — AI 问答真实化 + 农业限定（问题 1 后半）

### 轮次 R8 — 菜单与权限收口（问题 7/8）

### 轮次 R10 — 棚主管理（问题 12）

- **Q1 · AI 接口与 Key 安全**：用户提供 DeepSeek API Key；嵌入继续使用 SiliconFlow bge-m3。Key 通过 gitignore 排除的本地文件 `.env.local` + 环境变量注入，仅后端使用，前端不接触；代码中只保留 `${DEEPSEEK_API_KEY}` 占位符。
- **Q2 · 地区数据来源**：选方案 A —— 从大棚五级地区字段（province/city/district/town/village）聚合生成层级；后端封装为独立地区服务接口，后续如需升级为标准行政区划表（方案 B）只替换该服务实现。
- **Q3 · 棚主管理"进入管理"**：选方案 A —— 管理员在页面内切换为该棚主视角，查看其名下数据总览/设备/预警，可一键切回管理员。
- **Q4 · 管理员数据总览环境数据**：选方案 A —— 显示地区聚合环境概览（温度/湿度/光照/CO2 平均值 + 在线农户数/大棚数），不显示农户明细。
- **附加确认**：地区健康评分按预警加权扣分（严重/警告/提示不同权重），规则后续可细化；知识库先修复 md/txt 上传 + 乱码 + 向量化；数据导出修复 Blob 下载并改为 OWNER/WORKER 专用；专家登录自动置在线、登出/断线置离线。
